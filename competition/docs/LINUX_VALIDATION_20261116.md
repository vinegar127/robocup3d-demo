- 首次七人短赛完成两半场且比分 0:0，但退出返回 -11（SIGSEGV），已作为失败保留，没有计为通过。
- 同配置诊断重跑正常退出，说明退出问题具有间歇性。
- 检查发现测试工具原先只等待服务端线程 2 秒，MuJoCo 移除多人时可能仍在重编译。修复 `tools/evaluate.py` 清理顺序：先结束客户端，再等服务端线程结束，避免 Python 退出时后台仍访问原生对象。比赛循环与球队算法未变。
- 两场在修复前启动的左场完整赛也在踢满 600 秒后返回 -11，比分分别为 My3D 3:0、Jenny 4:0。这两次运行不计为通过；修复后按相同种子重新执行左场，所有尝试保留在 comparison.json。
- 本次生成的两个约 2 GB core dump 已清理。后续验证设置 RLIMIT_CORE=0，并启用 Python faulthandler；系统 apport 管道仍可能绕过 core 大小限制，未更改系统崩溃收集设置。原始比赛日志、退出码及源码快照保留。
- My3D 使用原始 POSIX 源码原生构建、自己的 assets 与官方 Linux ONNX Runtime 1.22.0 SDK；yaml-cpp 0.8.0 编译至项目内。通过 CMake 的 include 参数补齐 main.cc 对项目内 yaml-cpp 头文件的搜索路径，未改对手源码。
- 新增 `run_match_linux.sh`，用法：`bash run_match_linux.sh`；图形显示默认完整自对赛。
